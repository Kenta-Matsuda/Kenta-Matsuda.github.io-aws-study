# AIチャットが実在する試験を「存在しない」と否定し別試験にすり替える問題（MCP による一次情報グラウンディング）

🔴 未対応（要対応）

- 種別: 要人間対応（リモート MCP 連携の公式仕様確認 / CORS・認証・レート制限）
- 関連: #138（関連 #109 / PR #113 / PR #135 / PR #139）

## 症状

AIB-C01（AWS Certified AI Business Strategist、リポジトリ内 `js/data/aib-c01.js` に定義済み）についてAIチャットに質問したところ、次のように誤った回答が返った。

> AWS Certified: SAP on AWS - Specialty (PAS-C01) の試験対策における重要なポイントを整理します。 ※現在、SAP on AWSの試験コードは「PAS-C01」となります。AIB-C01という名称は存在しないため、PAS-C01に関する内容として解説します。

実在する AIB-C01 を「存在しない」と断定し、無関係な PAS-C01 / SAP on AWS の内容にすり替えて回答してしまっている。

## 推定原因

- チャットのシステムプロンプト（`js/chat.js` の `buildChatSystemPrompt(exam)`）が、学習中の試験について試験コード（`code`）と略称（`shortLabel`）しか注入しておらず、正式名称・区分といった正確なメタデータや「この試験は実在するので否定・すり替えしない」という明示的なグラウンディングルールを与えていなかった。
- そのためモデルが、学習データ上の知識（AIB-C01 を知らない、あるいは別コードと混同）に引きずられ、リポジトリが保持する一次情報より内部知識を優先してしまった。
- issue #138 で理想として言及された「AI に AWS MCP を読ませて一次情報を確認させる」挙動について、当初の本ドキュメントは「ブラウザ実行の静的サイト（GitHub Pages）からは直接実現できず、サーバー側プロキシ／バックエンドが必須」と記していた。しかし PR #139 のメンテナー指摘のとおり、この前提は誤りである。AWS はホスト型（マネージド）のリモート MCP（AWS Knowledge MCP Server / AWS Knowledge Tools と呼ばれるもの。※正式名称は「公式ドキュメントで要確認」）を提供しているとされ、ブラウザの静的サイトからでもリモート HTTP エンドポイントは直接呼び出せる。実際、本リポジトリの `js/gemini.js` は `buildUrl`（およそ 49-51 行目）で `https://generativelanguage.googleapis.com/...` を組み立て、ユーザーが保存した API キーを付けて `fetch()`（およそ 176 行目 / 265 行目）でブラウザから直接叩いている。つまり「静的サイトはリモート HTTP を呼べない」わけではなく、実際の制約は CORS（対象エンドポイントがブラウザ発のクロスオリジン要求を許可しているか）と認証（キー等の受け渡し）である。したがって自前バックエンドの新設は必須ではなく、リモート／ホスト型 MCP であればクライアントから直接呼び出せる可能性がある。ただし対象エンドポイントの CORS 許可・認証方式は本環境（外部ネットワーク遮断）では検証できていないため、「公式ドキュメントで要確認」とする。

## 切り分け手順

1. `js/data/aib-c01.js` に AIB-C01 の定義（`code: 'AIB-C01'`, `title: 'AWS Certified AI Business Strategist'`, `shortLabel: 'AIB'`, business カテゴリー）が存在することを確認する（実在する試験であることの根拠）。
2. `js/chat.js` の `buildChatSystemPrompt(exam)` が学習中の試験のどのメタデータをプロンプトに注入しているかを確認する。
3. クライアント側グラウンディング（試験メタデータ注入 + 否定・すり替え禁止ルール）を強化したうえで、同様の誤答が再現するかを確認する。
4. `js/gemini.js` の `buildUrl`（およそ 49-51 行目）と `fetch()` 呼び出し（およそ 176 行目 / 265 行目）を確認し、ブラウザの静的サイトから外部の HTTP エンドポイント（`https://generativelanguage.googleapis.com`）をユーザーのキー付きで直接呼べている事実を確認する（＝リモート／ホスト型 MCP もクライアントから直接呼べる可能性がある根拠）。
5. 対象となるリモート MCP の正式なエンドポイント名・認証方式・CORS 許可の有無を公式ドキュメントで確認する（本環境では外部ネットワークが遮断されており未検証。「公式ドキュメントで要確認」）。
6. その上で、クライアント側だけで前進できる範囲（プロンプトグラウンディング、出典 URL の可視化、将来的なクライアント側リモート MCP ツール呼び出し）と、人間対応が残る範囲（レート制限・秘匿情報の扱い・公式仕様の実地確認）を切り分ける。

## 要人間対応事項

### 前提の訂正（PR #139 のメンテナー指摘を反映）

本ドキュメントは当初「一次情報の MCP 確認はブラウザ静的サイトでは不可能で、サーバー側プロキシ／バックエンドが必須」と記していたが、これは誤りだった。AWS はホスト型（マネージド）のリモート MCP（AWS Knowledge MCP Server / AWS Knowledge Tools。※正式名称は「公式ドキュメントで要確認」）を提供しているとされ、ブラウザの静的サイトからでもリモート HTTP エンドポイントは直接呼び出せる（`js/gemini.js` が `https://generativelanguage.googleapis.com` をユーザーキー付きで直接 `fetch` している実例がある）。実際の制約は「不可能」ではなく CORS と認証であり、自前バックエンドの新設は必須ではない。以下、前進可能な範囲と残る人間対応を分けて整理する。

なお、本環境は INTEGRATIONS_ONLY（外部ネットワーク遮断）であり、AWS 公式の MCP ドキュメント URL（`docs.aws.amazon.com/agent-toolkit/.../mcp-server.html`）は HTTP 403 で取得できず検証できなかった。そのため対象 MCP の**正式なエンドポイント名・認証方式・CORS 許可の有無は本ドキュメントでは事実として断定せず、すべて「公式ドキュメントで要確認」とする**。本件で AWS リソースへの操作は一切行っていない。

#### (1) クライアント側で追加バックエンド無しに前進できる範囲

- 【対応済み】`js/chat.js` の `buildChatSystemPrompt(exam)` に、学習中の試験の正確なメタデータ（正式名称 `title` / 試験コード `code` / 略称 `shortLabel` / 区分ラベル）をリポジトリの一次情報（`js/data/*.js`、`js/exams.js` の `EXAM_CATEGORIES`）から注入。
- 【対応済み】「リポジトリが提供する試験情報が信頼できる正であり、この試験は実在するので、否定・改名・別試験へのすり替えをしてはならない。実在・名称・コード・区分は内部知識より優先する」という明示的なグラウンディングルールを日本語・英語の両プロンプトに追加。
- 【今後クライアント側で可能】解説や回答が参照した出典 URL の可視化・引用（PR #135 / #109 の方向性の延長）。
- 【今後クライアント側で可能】ホスト型リモート MCP が CORS と認証の条件を満たす場合、`js/gemini.js` の直接 `fetch` と同様に、クライアントから直接リモート MCP を呼び出してモデルにツール実行させる経路。自前バックエンドの新設は前提ではない（対象エンドポイントの CORS・認証は「公式ドキュメントで要確認」）。

#### (2) 残る要人間対応

- リモート MCP のレート制限・クォータの扱い（超過時のフォールバックやユーザー通知の設計）。
- リモート MCP が要求し得る秘匿情報・認証情報の扱い（キーをクライアントに置くことの是非、露出リスク、ユーザー入力キー方式か否か）。
- 対象リモート MCP の**正式なエンドポイント名・認証方式・CORS 許可の有無**の実地確認（本環境では未検証。「公式ドキュメントで要確認」）。
- 上記の一次情報グラウンディングと LLM-as-judge の検証は、#109（アンブレラ）および PR #113 で扱っている MCP グラウンディング方針と重複しないよう整合を取ること。PR #135 は解説の出典 URL のクライアント側グラウンディングであり、本件の試験アイデンティティのグラウンディングとは対象が異なる。
- 本ドキュメントは公式仕様の確認という人間対応が残る範囲を扱うものであり、AWS CLI による直接のリソース操作は不要（そのため「⚠️ 要人間対応: AWS操作が必要」ブロックは設けない）。
