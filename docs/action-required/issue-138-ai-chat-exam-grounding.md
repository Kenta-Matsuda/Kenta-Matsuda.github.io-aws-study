# AIチャットが実在する試験を「存在しない」と否定し別試験にすり替える問題（MCP による一次情報グラウンディング）

🔴 未対応（要対応）

- 種別: 要人間対応（バックエンド / MCP 連携）
- 関連: #138（関連 #109 / PR #113 / PR #135）

## 症状

AIB-C01（AWS Certified AI Business Strategist、リポジトリ内 `js/data/aib-c01.js` に定義済み）についてAIチャットに質問したところ、次のように誤った回答が返った。

> AWS Certified: SAP on AWS - Specialty (PAS-C01) の試験対策における重要なポイントを整理します。 ※現在、SAP on AWSの試験コードは「PAS-C01」となります。AIB-C01という名称は存在しないため、PAS-C01に関する内容として解説します。

実在する AIB-C01 を「存在しない」と断定し、無関係な PAS-C01 / SAP on AWS の内容にすり替えて回答してしまっている。

## 推定原因

- チャットのシステムプロンプト（`js/chat.js` の `buildChatSystemPrompt(exam)`）が、学習中の試験について試験コード（`code`）と略称（`shortLabel`）しか注入しておらず、正式名称・区分といった正確なメタデータや「この試験は実在するので否定・すり替えしない」という明示的なグラウンディングルールを与えていなかった。
- そのためモデルが、学習データ上の知識（AIB-C01 を知らない、あるいは別コードと混同）に引きずられ、リポジトリが保持する一次情報より内部知識を優先してしまった。
- issue #138 で理想として言及された「AI に AWS MCP を読ませて一次情報を確認させる」挙動は、ブラウザ実行の静的サイト（GitHub Pages）からは直接実現できない。リモート MCP への接続やツール実行にはサーバー側プロキシ／バックエンドが必要になる。

## 切り分け手順

1. `js/data/aib-c01.js` に AIB-C01 の定義（`code: 'AIB-C01'`, `title: 'AWS Certified AI Business Strategist'`, `shortLabel: 'AIB'`, business カテゴリー）が存在することを確認する（実在する試験であることの根拠）。
2. `js/chat.js` の `buildChatSystemPrompt(exam)` が学習中の試験のどのメタデータをプロンプトに注入しているかを確認する。
3. クライアント側グラウンディング（試験メタデータ注入 + 否定・すり替え禁止ルール）を強化したうえで、同様の誤答が再現するかを確認する。
4. MCP による一次情報確認が必要かどうか、クライアントだけで完結できない範囲を切り分ける。

## 要人間対応事項

本 PR で対応済み（クライアント側で前進できた範囲）:

- `js/chat.js` の `buildChatSystemPrompt(exam)` に、学習中の試験の正確なメタデータ（正式名称 `title` / 試験コード `code` / 略称 `shortLabel` / 区分ラベル）をリポジトリの一次情報（`js/data/*.js`、`js/exams.js` の `EXAM_CATEGORIES`）から注入。
- 「リポジトリが提供する試験情報が信頼できる正であり、この試験は実在するので、否定・改名・別試験へのすり替えをしてはならない。実在・名称・コード・区分は内部知識より優先する」という明示的なグラウンディングルールを日本語・英語の両プロンプトに追加。

人間（またはバックエンド権限を持つ者）による将来対応:

- issue #138 が理想とする「AI が AWS MCP を読んで一次情報を確認する」フローは、ブラウザ実行の静的サイトからは直接実現できない。リモート MCP（AWS ドキュメント等の一次情報源）へ接続し、モデルにツール実行させるためのサーバー側プロキシ／バックエンドの設計・構築が必要。
- この MCP 連携による一次情報グラウンディングと LLM-as-judge の検証は、#109（アンブレラ）および PR #113 で扱っているバックエンド / MCP グラウンディング方針と重複しないよう整合を取ること。PR #135 は解説の出典URLのクライアント側グラウンディングであり、本件の試験アイデンティティのグラウンディングとは対象が異なる。
- 本ドキュメントは MCP／バックエンド連携という人間対応が必要な範囲を残すものであり、AWS CLI による直接のリソース操作は不要（そのため「⚠️ 要人間対応: AWS操作が必要」ブロックは設けない）。
