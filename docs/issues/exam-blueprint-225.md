# 模擬試験の出題構成・正解位置・参照リソースをコードで決める (#225 Step A / B)

## 背景（issue #225）

フィードバックフォームからの要望（要約）:

> 模擬試験は推奨リソースを参考に作るべき。ドメイン/タスクごとの出題数を決め、タスクごとに参照リソースを決め、その内容を読み込んで問題と解説を作り、シャッフルして出題する。シャッフルなどエージェント不要な部分はエージェントを使わない。

全体の設計と段階導入案（Step A〜D）は `docs/action-required/issue-225-resource-grounded-exam-generation.md`（PR #227）にあります。本対応はそのうち **Step A（出題構成と正解位置）** と **Step B（推奨リソースのメタデータによるグラウンディング）** です。リソース本文の読み込み（Step C 以降）は含みません（`Refs #225`）。

## 変更前の問題

- ドメイン比率どおりに出題枠は割り当てていたが、**どのタスクから出すかはモデルに「ランダムに選んで」と任せていた**ため、タスクの偏り・抜けが起きうる。
- **正解の位置（A〜D）はモデル任せ**で、特定の記号に偏りやすい。

## 実装したもの

`js/quiz.js` にピュア関数を追加（乱数は注入可能で単体テスト可）:

- `assignTaskTargets(domains, count, rng)`: 既存の `assignDomainTargets` でドメイン比率の枠を決めた後、各ドメインの枠を**そのドメインのタスクへ均等に**割り当てる（全タスクを一巡してから重複）。各枠は `{ domain, task }`。
- `assignAnswerLetters(count, rng)`: 正解記号を A〜D に**均等配分**してシャッフル。
- `buildAnswerPositionHint(letter)`: 「正解は選択肢 X に配置する」というプロンプト追記。
- `buildGeneralQuizUserPrompt(examCode, domain, task)`: タスクが指定されたらタスク ID・タイトル・**タスクステートメント全文**をプロンプトに含め、ランダム選択の指示を出さない（タスク未指定時の文言は従来どおり）。

`js/ui.js` の 3 経路（事前生成ループ / Gemini Batch / 単発生成）で上記を使用。生成した問題には `taskId` も記録します。

## 考慮したトレードオフ

- **選択肢を生成後にシャッフルしない**: 解説が「A は誤り、B が正解…」と記号で選択肢を参照するため、後から並べ替えると解説と食い違う。代わりに正解位置を**生成前にコードで決めてプロンプトで指示**する方式にした。モデルが指示に従わなかった場合も、返された `correct` をそのまま使うので採点は壊れない。
- タスクステートメント全文を渡すぶん、ダッシュボード経由の 1 問あたりの入力トークンはわずかに増える（タスク別クイズでは従来から渡している量と同程度）。

## Step B: 推奨リソースに基づく出題

`js/quiz.js` にピュア関数を追加:

- `rankTaskResources(task)`: タスクのリソースを「公式ドキュメント > ホワイトペーパー / Builders' Library / Knowledge Center > ブログ / re:Post > 製品ページ」の順、同順位では `recommend: true` 優先で並べる。Black Belt（概要ページへのテキストフラグメントリンク）・トレーニング・ハンズオンは出典に使えないため除外。
- `selectTaskResources(task, occurrence, limit=3)`: 上位から 3 件。同じタスクから複数問出すときは窓をずらし、問題ごとに別のリソースを使う。
- `buildResourceGroundingHint(resources)`: 「【参照リソース】タイトル — URL (note)」をプロンプトに追加し、それらの内容に基づいて作問し、解説ではこの一覧の URL を引用するよう指示（一覧外の URL の捏造を禁止）。
- `appendMissingResourceRefs(explanation, resources)`: 解説がどのリソースも引用していなければ「参考リソース」としてリンクを末尾に追加。学習者は必ず厳選リソースへ辿れる。

`js/ui.js` の 3 経路すべて（ダッシュボード経由・タスク別クイズ・Batch）で使用。URL は `getLocalizedUrl` で表示言語に合わせる。全 13 試験・206 タスクのすべてで 1 件以上の引用可能リソースが選ばれることをテストで確認。

**制約**: 渡すのはタイトル・URL・note の**メタデータのみ**で、ページ本文は読ませていない（ブラウザからは CORS で取得不可）。本文読み込みは Step C（Gemini `url_context`、トークン増のため要判断）。

## 検証

- `tests/exam-blueprint.spec.mjs`: 配分（ドメイン比率の維持・タスク間の差が 1 以下・全タスク網羅）、正解記号の均等性、プロンプト内容、さらに Gemini をスタブして**実際のスピードチャレンジ 10 問の送信プロンプト**にタスク・参照リソース・正解位置が入ること、**タスク別クイズ**でそのタスクの推奨リソースがプロンプトに入り、未引用時に解説へ「参考リソース」リンクが出ることを確認。
