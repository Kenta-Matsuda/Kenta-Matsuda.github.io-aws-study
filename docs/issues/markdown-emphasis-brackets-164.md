# Issue: AI 解説の `**「…」**` が太字にならず「**」がそのまま表示される問題 (#164)

## 概要

issue #164 のフィードバック。

> **「誰が聞いても同じ意味で伝わるように用語や概念を整理したもの」** のように、ai 生成した解説文には、
> markdown にレンダリングできてない部分がある。これは「」が含まれていることが原因で、アスタリスクで
> 囲ったら半角や全角でスペースを空けないとうまくレンダリング出来ないらしい。

## 原因（CommonMark の flanking ルール）

報告どおり、原因は**強調の内側が日本語の括弧で始まり / 終わっていて、かつ強調がかなに直接くっついている**ことです。

```
次の**「誰が聞いても同じ意味で伝わるもの」**のように
```

CommonMark では、`**` の delimiter run が**句読点に続く**場合、その直前の文字が空白または句読点でなければ
left-flanking になりません。上の例では

- 開き `**`: 直前が `の`（文字）、直後が `「`（句読点）→ **left-flanking にならない**
- 閉じ `**`: 直前が `」`（句読点）、直後が `の`（文字）→ **right-flanking にならない**

となり、どちらの run も強調に参加せず、アスタリスクがそのまま出力されます。`**「用語」**` 単独や
`これは**太字**です` は条件を満たすので正しく太字になります。つまり**括弧つきの強調がかなに密着したときだけ**
壊れる、という限定的な条件でした。

## 対応

`normalizeMarkdownForJapanese()` に、**必要な側にだけ半角スペース 1 個を外側へ挿入する**処理
（`padEmphasisForFlanking`）を追加しました。報告にあった回避策そのものを、条件を満たす箇所に限って
自動適用する形です。

```
次の**「…」**のように   →   次の **「…」** のように
```

- 挿入するのは「強調の内容が句読点で始まる / 終わる」かつ「隣の文字が空白でも句読点でもない」場合だけ。
  既に正しくレンダリングされる文には手を入れないため、余分な空白は増えません。
- 既存の正規化（全角アスタリスク `＊＊` の変換、ゼロ幅文字の除去、`** 「…」 **` のように内側に入った
  空白の除去）はそのまま維持し、内側の空白除去 → 外側のスペース挿入の順で適用します。
- フェンスドコードブロックとインラインコードは従来どおり対象外です。

### 併せて行った切り出し（AI チャットにも同じ修正が効くように）

正規化とレンダリングを `js/ui.js` から **`js/markdown.js`** へ切り出しました。

- 理由 1: DOM 不要な純ロジックとして単体テストできるようにするため（`tests/markdown-normalize.spec.mjs`）。
- 理由 2: `js/chat.js`（AI チャット）は `marked.parse()` を直接呼んでおり**正規化を通していなかった**ため、
  同じ表示崩れが起きていた。共有の `renderMarkdownToSafeHtml()` を使うように変更し、解説モーダルと
  チャットで挙動を揃えた。

## 検証

- `tests/markdown-normalize.spec.mjs`（13 テスト）
  - 報告された実例が期待どおりパディングされること
  - 片側だけ必要なケース / 既に正しい文を変更しないこと / 隣が句読点なら何もしないこと
  - `***`（太字 + 斜体）、内側空白の除去、全角アスタリスク変換、コードブロック・インラインコードの非改変
  - アスタリスクの個数が変わらないこと、空文字・null が安全なこと
  - **アプリが実際に読み込む `marked`** で、修正前の文字列は `**` が残り `<strong>` にならず、
    正規化後は `<strong>` になり `**` が消えることをブラウザ上で確認（診断の裏取り）
- `npx playwright test`（全 36 テスト）成功
