# Issue: フィードバックのハードルを下げる（#100 / #101）

## 概要

フィードバック機能について、密接に関連する2件の要望に対応する。

- **#100**: フィードバックをもっと気楽に送れるようにしたい。「フィードバックしませんか？」といった軽いポップアップや、「あなたの声が利用者4,000人超のサービス改善につながる」といった訴求で、心理的ハードルを下げたい。
- **#101**: フィードバックを GitHub の Issue 画面を出さずに送れないか。そもそも GitHub アカウントが必須だと思われてしまい、送信をためらう人がいる。

本サイトはビルドステップの無い静的 PWA（GitHub Pages 配信）で**バックエンドを持たない**ため、サーバーでフィードバックを受け取ることはできない。この構造的制約を踏まえ、**クライアント側で現実的に下げられる摩擦だけ**を対象に改善する。

## 変更内容

### 1. 軽量フィードバックナッジ（#100）

- 画面左下に、**却下可能な小さなプロンプト（トースト）** を追加（`#feedbackNudge`）。
- 「ひとことフィードバックしませんか？」＋「あなたのご意見が、利用者4,000人超のサービスの改善につながります。」という訴求文言。
- **一定回数の問題に解答したあと（初回ロード時ではなく、実際に使ってくれたタイミング）** に一度だけ表示する。
- 「フィードバックする」で既存のフィードバックモーダルを開く。「あとで」「×」で閉じる。
- 表示/却下の状態を `localStorage`（`asn_feedback_nudge_v1`）に永続化し、**一度対応・却下したら再表示しない**。既存の `FEEDBACK_XP_DAY_KEY` 等と同じ localStorage パターンに従う。
- あくまで任意の導線であり、既存のフィードバックボタン・モーダルは常に利用可能。

### 2. GitHub アカウント不要の導線を明確化（#101）

- フィードバックモーダルに **「GitHubアカウントは不要」であることを明示する注記** を追加。
- **「テキストをコピー」ボタン** を追加し、入力内容を（カテゴリ付きの整形済みテキストとして）クリップボードにコピーできるようにした。GitHub の Issue 画面を一切開かずに、ユーザーが好きな手段（開発者への連絡など）で送れる経路を明確にした。
- コピー経路と Issue 投稿経路は同一の整形ロジック（`composeFeedbackIssue`）を共有し、内容とエスケープが一致するようにした。

### 3. i18n

- ユーザー向け文言はすべて i18n 経由。`js/locales/ja.json` と `js/locales/en.json` の両方に追加し、両ファイルのキー集合が完全な相互ミラーになるようにした。
- 追加キー: `feedbackModal.noAccountNote` / `feedbackModal.copyText` / `feedbackModal.copied` / `feedbackModal.copyFailed`、および `feedbackNudge.{title,body,open,dismiss}`。

## 技術的な実装方針

- 新規ライブラリは導入しない。既存のトースト/モーダルのマークアップと CSS パターン、既存の `copyTextToClipboard` / `showInlineMessage` / `t()` ヘルパーを再利用。
- ナッジ表示条件は `getQuizHistory().length >= FEEDBACK_NUDGE_MIN_QUESTIONS`（実際の利用後にのみ表示）。
- 状態永続化は localStorage の best-effort（書き込み失敗が UI を壊さないよう try/catch）。

## 考慮したトレードオフ（重要）

- **バックエンドが無いという構造的制約は解消していない。** #101 の「GitHub 画面を一切出さず／アカウント不要で完結」を**完全に**満たすには、フィードバックを受け取るサーバー（またはフォーム SaaS 等の外部サービス）が必要になる。本サイトは静的 PWA でありサーバーを持たない方針のため、外部サービスも含めて**導入していない**。
- そのため本対応は、**クライアント側で下げられる摩擦のみ**を対象とした改善である。具体的には (a) アカウント不要で使える「テキストをコピー」経路を目立たせ・明文化し、(b) モーダル文言でアカウント不要であることを明確化した。これにより、GitHub アカウントを持たない/使いたくないユーザーにも実用的な送信経路が残る。
- ナッジは繰り返し出さない設計にし、押しつけ感を避けた（表示は原則一度きり）。

## 受入条件

- [x] 却下可能なフィードバックナッジが存在し、表示/却下状態が localStorage に永続化される（却下後は再表示されない）
- [x] フィードバックモーダルの文言で「アカウント不要／コピー経路」が明確化されている
- [x] 追加したユーザー向け文言が ja.json / en.json の両方に存在し、キー集合が相互ミラーである
- [x] 既存機能（クイズ、XP、フィードバック送信、画像添付等）に影響がない
