# 問題生成を多段化する: 設計図 → 計画 → 作問 → 重複検査 (#225 / PR 4)

## 背景

設計書 [`../design/exam-generation-pipeline.md`](../design/exam-generation-pipeline.md) §5 の段 0〜3 の実装（段階導入計画の PR 4）。

AIB-C01 の模擬試験で「AI CoE を設置する」が正解の問題が繰り返し出た。原因は、1 問ずつ孤立して生成し、重複回避が「直近 5 問の問題文の先頭 80 文字」しか見ていなかったこと（正解の**概念**の重複を見ていない）、Batch では重複回避が無かったこと、抽象的な試験では「違うサービスで」が効かないこと。プロンプトの調整ではなく、生成の仕組みを多段に変える。

## 実装したもの

### `js/examPipeline.js`（新規・純ロジック）

| 段 | 関数 | 内容 |
|---|---|---|
| 0 設計図 | `buildExamBlueprint({ exam, count, task?, level, rng })` | 1 問 = 1 スロット。ドメイン/タスク（比率配分）、**タスクステートメントの箇条書き 1 項目**（`extractTaskItems`、タスク内で一巡してから重複）、設問タイプ（7 種）、視点（Business 試験は経営層/人事/法務…、技術試験はアーキテクト/開発者/運用…）、業種（10 種）、正解位置。`compactBlueprint` で ExamSet に保存できる形にする |
| 1 計画 | `buildPlannerPrompt` / `parsePlan` / `validatePlan` | 1 回の呼び出しで全スロットの「正解が問う概念」「シナリオの種」「誤答の方向性」を JSON 配列で得る。**概念は試験全体で一意**を厳守させ、近似重複（英数字は単語・日本語は文字 bigram の Jaccard 類似度 ≥ 0.6。語尾のひらがなは無視）はコードで落とす。5 問未満のセッションでは省略 |
| 2 作問 | `buildSlotPromptSuffix({ slot, plan, banned })` | 「問う項目／設問タイプ／視点・業種／正解が問う概念（これに限定）／シナリオの種／誤答の方向性」と、**使用済み概念（正解にしてはいけない）**をプロンプトに追加。計画が無いスロットには他スロットの計画概念も禁止リストに入れる（上限 40） |
| 3 検査 | `isDuplicateQuestion` / `buildDuplicateRetryHint` / `summarizeDiversity` | 生成結果の正解選択肢（類似度 ≥ 0.7）または問題文（≥ 0.75）が既出と近ければ、重複した正解を名指しして **1 回だけ再生成**。再生成でも改善しなければ欠番より近似重複を採る。正解のクラスタ数・最大クラスタをメトリクスとして記録 |

LLM が要らない段（0 と 3、1 の検証）はすべてコードで決定的に行い、計画の失敗・解釈不能は作問を止めずに設計図のみで続行する（設計原則）。

### `js/ui.js`

- 事前生成（スピード/模擬）、Gemini Batch、単発/5 問連続の 3 経路で上記を使用。従来の `assignTaskTargets` / `assignAnswerLetters` の直接利用は設計図に置き換え、「直近 5 問の問題文」ヒントは廃止。
- 計画と設計図は問題セット（PR 2）に保存（`pipeline.stage`: planning → writing → ready）。Batch では計画を送信前に同期で 1 回だけ実行し、スロット情報に出題項目（`unitId`）も残す。
- 各問題に `unitId`（問うた項目）を付け、完了時に `metrics`（重複再生成数・クラスタ数・最大クラスタ）を記録。

## コスト

試験 1 回あたり **計画 1 回**（65 スロットで入力 3〜4k・出力 3k トークン程度）＋ 重複時の再生成（通常 0〜数回）が増える。本文読み込み（Step C）は含まない。

## スコープ外（後続）

- カード（ケースカード／フレームワーク・マップ）からの出題単位の供給（PR 5）。現状の出題単位はタスクステートメントの箇条書き。
- Judge / Solver / Editor と回帰評価スクリプト（PR 6）。

## 検証

`tests/exam-pipeline.spec.mjs`:

- 純ロジック: 項目抽出、AIB 65 問の設計図が 13 タスク全部を使い、タスク内で項目が一巡し、正解位置が均等で、設問タイプ 7 種を全部使う。計画の解釈（フェンス・前置き・スロット番号順不同）、日本語の言い換え重複の除去、プロンプトの内容と禁止リスト上限、重複判定とクラスタ集計。
- ブラウザ（Gemini スタブ）: AIB のスピードチャレンジで **計画呼び出しが 1 回、作問が 10 + 再生成 1 = 11 回**。全作問プロンプトに出題設計と計画概念が入り、3 問目の重複した正解を名指しした再生成が 1 回だけ起きる。セットは `ready`・10 問・`unitId` 付き・計画と設計図が保存され、メトリクスに再生成 1・最大クラスタ ≤ 2 が記録される。
