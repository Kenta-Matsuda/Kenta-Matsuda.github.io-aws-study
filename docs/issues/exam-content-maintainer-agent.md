# Issue: 試験作成/更新用エージェントの作成と最適化 (#69)

## 概要

`js/data/` 配下の全 AWS 試験学習リソースを、日々の AWS ドキュメント更新に追随して継続的に保守するためのエージェントを整備する。issue #69 で確定した要件は次のとおり。

- 掲載中の AWS 公式ドキュメントを見直し、より良い最新のリソースへの**入れ替え・削除・追加**を行う。
- 上記作業を通じて**自己学習し、どんどん賢くなっていく**（より効率的・より低コスト＝トークン消費的に）ようにする。具体的には以下の仕組みを備える:
  - より良い AWS 公式リソースを検索するための**ノウハウを永続化・最新化（棚卸し）**する仕組み。
  - 自身の作業を振り返り、**効率化・低コスト化（作業のスクリプト化によるトークン削減）**を検討する仕組み。
  - 必要に応じて、**自身のプロンプトや能力（skill 等）を自ら拡張**する仕組み。
  - 要するに「自分で仕組みを考えて実装できる」エージェントにする。
- 棚卸し対象は**全ての試験**（`js/data/` 配下）。web 検索で最新情報に差し替えたり、古い既存ドキュメントを切り替える。
- 獲得したノウハウの**ドキュメント化は `docs/` へ**。**LLM Wiki** 形式とする（ただし最新化・過去ドキュメントとの整合性確保ができる前提）。
- 実行は利用者が設定する **Kiro automations** で行う想定。エージェント設定（`.kiro/` 配下のエージェント）のみ用意すればよく、**GitHub Actions は不要**。

## 変更内容

- `js/data/` 配下の全 13 試験（`aibs-c01`, `aif-c01`, `aip-c01`, `ans-c01`, `clf-c02`, `dea-c01`, `dop-c02`, `dva-c02`, `mla-c01`, `saa-c03`, `sap-c02`, `scs-c03`, `soa-c03`）のリンク（`resources[].items[].url` / `urlEn`）を棚卸しし、差し替え・削除・追加する保守エージェントを定義。
- 既存 `.kiro/agents/github-issue-resolver.md` の書式（YAML フロントマター + 日本語本文、`permissions.rules` による許可 / 拒否）に合わせる。
- 主要機能として、(1) リソース棚卸し、(2) 探索ノウハウの LLM Wiki への永続化・最新化、(3) 自己レビューによる効率化・低コスト化、(4) 自己拡張（プロンプト・skill の改善）を規定。
- 成果物は必ず **PR ベースで人間レビュー**を経てマージし、`main` へ直接反映しない。

### 2. LLM Wiki の土台（`docs/wiki/`）
- `docs/wiki/README.md` — LLM Wiki の目的・置き場所・**ページスキーマ（最終更新日 + 更新履歴）**・更新（最新化）ルール・**過去ドキュメントとの整合性確保ルール**・索引運用・現在のページ一覧を定義。
- `docs/wiki/aws-resource-discovery.md` — より良い AWS 公式リソースを探すための信頼ドメイン一覧・検索クエリの型・評価基準・死活/鮮度チェックの観点。

### 3. 索引の更新（`docs/index.md`）
- 「LLM Wiki（docs/wiki/）」セクションを追加し、上記 4 ファイルへリンク。
- issue 解説セクションに本ドキュメントへのリンクを追加。デッドリンク・孤立ファイルを作らない。

## 設計方針・トレードオフ

- **なぜ LLM Wiki か**: 獲得したノウハウを構造化して永続化・再利用し、エージェントが継続的に賢くなれるようにするため。ただし利用者の確定条件どおり、**最新化（棚卸しによる更新）と過去ドキュメントとの整合性確保が可能であること**を前提に採用する。そのため README で、各ページに**最終更新日 + 更新履歴**を必須化し、矛盾は出典で片側に寄せて統一・記録し、古い記述は単純削除でなく更新し理由を残す、重複ページを作らない、相対リンクは実在必須、といった具体ルールを定義した。
- **PR ベースの人間レビュー**: リソースの差し替えや自己改変（プロンプト・skill・権限）は影響が大きいため、必ず PR を経て人間がレビューする。権限緩和は特に慎重に扱う。
- **web 検索・データ書き換えは「記述するが実行しない」**: 本タスクのサンドボックスは INTEGRATIONS_ONLY（外部ネットワーク不可）であり、web 検索・実アクセスによるリンク検証や実データ書き換えは実行できない。これらは**手順・判断基準・成果物の形**として記述し、実際の実行は利用者の Kiro automations（ネットワーク可能環境）に委ねる。
- **GitHub Actions は不要**: 利用者が Kiro automations を自分で設定するため、CI ワークフローは作らず、エージェント定義と Wiki 土台のみを用意する。

## スコープ外

- 実際の**試験データ（`js/data/*.js`）の書き換え**（リンクの差し替え・削除・追加の実施）。
- **web 検索・外部リソースへの実アクセスによる検証**の実行（ネットワーク制約のため）。
- Kiro automations の設定そのもの（利用者が実施）。
- GitHub Actions などの CI ワークフロー。
