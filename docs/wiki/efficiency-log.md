# 効率化・自己拡張ログ

- 最終更新日: 2026-09-06
- 対象範囲: 作業の効率化・低コスト化（繰り返し作業のスクリプト化によるトークン削減）の検討ログと、自己拡張（プロンプト・skill の改善）提案ログ
- 出典/参照: issue #69 / `.kiro/agents/exam-content-maintainer.md` / `.kiro/agents/github-issue-resolver.md` / `scripts/check-resource-links.mjs` / `scripts/list-aws-doc-pages.mjs`

> エージェントが実行のたびに自分の作業を振り返り、**トークン消費と手間を減らす**アイデアと、**自分自身の能力を拡張する**提案を記録するログです。スキーマ（メタデータ + 更新履歴）は [README](README.md) を参照してください。

## ツールキット（実装済み / まずこれを使う）

棚卸しを始めるときは、URL を LLM が 1 件ずつ読む前に**必ず次のスクリプトを実行**し、要約だけを読み込んでください。

| スクリプト | 役割 | 代表的な実行例 |
| --- | --- | --- |
| `scripts/check-resource-links.mjs` | `js/data/` 全試験から `url` / `urlEn` を抽出し、HTTP 死活・リダイレクト・ソフト 404・テキストフラグメントの陳腐化を分類して一覧化 | `node scripts/check-resource-links.mjs --concurrency 10 --fragments --json test-results/links-all.json` |
| `scripts/list-aws-doc-pages.mjs` | AWS 公式ドキュメント 1 ページから同一ガイド内の下位ページ / ページ内アンカーを抽出 | `node scripts/list-aws-doc-pages.mjs <url> --titles` / `... --anchors` |

`check-resource-links.mjs` は差し替え候補の当たり付けにも使えます（`--urls "https://a,https://b" --all`）。候補を推測で書き込む前に、必ずこのモードで実在とリダイレクト先を確認してください。

## 記録の目的

- 「LLM が毎回自然言語で処理していた定型作業」を「スクリプト + 結果の要約読み込み」に置き換え、**コンテキスト投入トークンを削減**する。
- 効率化・自己拡張の**検討結果と効果（見込み / 実測）**を残し、次回以降の自分が参照できるようにする。
- 自己改変（プロンプト / skill / スクリプト）は必ず **PR ベース・人間レビュー前提**で提案する。

### 例: リンク死活チェックのスクリプト化

- **日付**: 2026-09-03（例）

- **想定効果（見込み）**: URL 一覧の生投入が不要になり、確認 1 巡あたりの投入トークンを削減。
- **状態**: アイデア（未実装）。実装時は `env -u NODE_OPTIONS node --check` で静的検証し、PR で提案する。

## 効率化ログ（実績）

### 2026-09-06: リンク死活チェックのスクリプト化（実装済み）

- **日付**: 2026-09-06
- **対象作業**: `js/data/*.js` の全 `url` / `urlEn` を LLM が抽出し 1 件ずつ確認していた作業。
- **課題**: 対象は 14 ファイル・**`url`/`urlEn` フィールド 1,771 件 / ユニーク URL 1,092 件**（実測）。自然言語で抽出・確認すると投入トークンが極端に大きく、再現性も低い。
- **実装**: `scripts/check-resource-links.mjs`。データファイルを動的 `import` して**深さ優先で `url`/`urlEn` を持つオブジェクトを収集**するため、スキーマが多少変わっても壊れない。HTTP は HEAD → GET フォールバックで確認し、結果を `broken` / `soft-404` / `error` / `server-error` / `fragment-miss` / `redirect` / `forbidden` / `locale-redirect` / `ok` に分類する。
- **実測効果**:
  - **リクエスト数削減**: フラグメント（`#...`）は HTTP では送られないため、フェッチを**フラグメント除去後の URL 単位**で重複排除。ユニーク URL 1,092 件 → 実 HTTP リクエスト **911 件**（Black Belt 一覧ページへのテキストフラグメント付きリンクが多いため）。フラグメント本文検証が必要なページはさらに **4 ページ**に収束した。
  - **投入トークン削減**: LLM が読むのは 1,092 行超の URL 一覧ではなく**問題行のみの要約**。初回実行の要約は `broken` 15 / `soft-404` 24 / `fragment-miss` 19 / `redirect` 67 / `forbidden` 4 の計 **129 件**まで絞られた（`ok` 757 件と `locale-redirect` 206 件は既定で出力しない）。読み込み量として概ね **1/8 以下**。
  - **判断品質の向上**: 分類を分けたことで「本当に直すべきもの」と「ノイズ」が分離された（下記の 2 つの落とし穴を参照）。
- **状態**: 実装済み。静的検証は `node --check scripts/check-resource-links.mjs` を通過。

### 2026-09-06: ガイド内ページ / アンカー列挙のスクリプト化（実装済み）

- **日付**: 2026-09-06
- **対象作業**: 「このガイドにもっと適切な章はないか」を LLM が推測し、候補 URL を当て推量で HTTP 確認していた作業。
- **実装**: `scripts/list-aws-doc-pages.mjs`。指定ページから同一ガイド配下の下位ページ（`--titles`）またはページ内見出しアンカー（`--anchors`）を抽出する。
- **実測効果**: 推測による候補生成と往復が不要になった。実例:
  - AIB-C01 試験ガイドに**ドメイン別ページと「スコープ内 / スコープ外サービス」ページが実在**することを 1 回の実行で確定（8 ページ）。
  - AWS CAF for AI ホワイトペーパーは**単一ページ構成**（下位ページは改訂履歴のみ、ページ内アンカーも 4 個）であることを確定。同一 URL を複数タスクで使い回すのは仕様上避けられないと結論でき、無駄な差し替え検討を打ち切れた。
  - SageMaker Clarify の後継ページ名（`clarify-configure-processing-jobs.html` = "Fairness, model explainability and bias detection"）を、推測ではなく目次から特定できた。
- **状態**: 実装済み。静的検証は `node --check scripts/list-aws-doc-pages.mjs` を通過。

## 自己拡張提案ログ（実績）

### 2026-09-06: 実行環境を断定しない前提への修正と、ツールキット優先の手順化

- **日付**: 2026-09-06
- **対象**: `.kiro/agents/exam-content-maintainer.md`（本エージェントのプロンプト）
- **提案内容**:
  1. **「サンドボックス実行環境の事実」を「実行環境の事実」に改題し、環境を断定しない前提に改めた。** 従来は「OS は Linux、シェルは bash」「INTEGRATIONS_ONLY 環境では外部アクセス不可」と断定していたが、実測で **Windows / PowerShell 7 かつネットワーク利用可能**な環境でも起動されることが判明した。
  2. **「手順 0: 着手時の環境判定」を新設**し、OS / シェル・`NODE_OPTIONS`・ネットワーク可否の 3 点を最初に確認することを必須化。判定結果を最終報告に明記させる。
  3. **PowerShell 環境固有の落とし穴を明文化**: ヒアドキュメント不可（コミットメッセージ / PR 本文はファイル経由で渡す）、`env -u NODE_OPTIONS` 不可（`$env:NODE_OPTIONS=''` を使う）、コンソール出力の日本語が CP932 で文字化けする（git 内部は正しい UTF-8 なので誤認しない / 長い出力はスクリプトから UTF-8 ファイルへ直接書き出す）。
  4. **「ツールキット」節を新設**し、`scripts/check-resource-links.mjs` / `scripts/list-aws-doc-pages.mjs` を棚卸しの第一手として使うこと、**候補 URL を推測で書き込まないこと**を手順・禁止事項の両方に明記。
  5. **「HTTP ステータスだけでは判定できない落とし穴」を要約して掲載**（ロケールリダイレクト / ソフト 404 / フラグメント陳腐化 / SPA ドメイン / 新規顧客の受付終了）。
  6. **検証節を具体化**: `js/data/` の URL を変更したら `--only <試験コード>` で 0 件を確認し、修正前後の件数を PR 本文に載せることを必須化。あわせて「URL / タイトル / 注記 / `recommend` のみの変更なら Playwright を省略してよい（ただし理由を PR に明記）」という判断基準を追加。
  7. **一時的な調査用スクリプトは gitignored な `test-results/tools/` に置く**ルールを追加（リポジトリを汚さない / 再利用価値が出たら `scripts/` へ昇格させて PR で提案）。
  8. ラベルが未定義のリポジトリでは先に作成が必要なこと、`gh api --jq` の式は PowerShell ではシングルクォートで囲むことを追記。
- **理由・期待効果**: 環境を断定していたため、Windows / PowerShell 環境では**プロンプト記載のコマンド（`env -u NODE_OPTIONS`、ヒアドキュメント）がそのままでは失敗**する。またネットワーク不可を前提としていたため、実際には可能な実地検証を「できない」と誤判断して手順整備だけで終える危険があった。環境判定を先頭に置き、ツールキットを第一手として固定することで、次回以降は同じ試行錯誤を繰り返さずに本題（リソースの是正）へ直行できる。
- **想定リスク**: 権限緩和・既存制約の削除は無し。既存の禁止事項はすべて維持し、制約の追加・具体化のみ。唯一の緩和方向の変更は「URL のみの変更なら Playwright 省略可」だが、**理由の明記を条件**にしており、従来の「実行できなければ理由を記録」運用の範囲内。
- **状態**: 実装済み（PR: `chore/agent-env-facts-and-tooling-first`）。

### 振り返り: なぜ今回まで全試験の棚卸しが手つかずだったのか

- **根本原因**: 対象規模（`url`/`urlEn` 1,771 フィールド / ユニーク 1,092 URL）に対して、検証手段が「LLM が自然言語で 1 件ずつ確認する」しかなかった。1 回の実行で終わる見込みが立たず、着手コストが高すぎた。加えてプロンプトが「外部アクセス不可」を断定していたため、**実地検証を諦める方向にバイアスがかかっていた**。
- **仕組みへの反映**: (1) 検証をスクリプト化して 1 回の実行で全件を分類できるようにした（`ok` と `locale-redirect` を出力から除外し、LLM が読むのは 129 件の要約のみ）。(2) プロンプトから断定的な環境前提を除去し、環境判定を必須化した。(3) 既知の URL 移転パターンを表として [AWS 公式リソース探索ノウハウ](aws-resource-discovery.md#既知の-url-移転パターン2026-09-06-実測) に蓄積し、次回は 1 件見つけたら同じパターンを全試験で検索できるようにした。

### 2026-09-05: コメントファースト前提条件の明文化とレトロスペクティブ/自己改善ループの制度化

- **日付**: 2026-09-05
- **対象**: `.kiro/agents/github-issue-resolver.md`（issue-resolver エージェントのプロンプト） / 本ログ `docs/wiki/efficiency-log.md`。
- **提案内容**:
  1. コメントファーストのハード前提条件を `手順` の先頭（新・手順 1）へ移設。どの issue でも、着手・見送り（スキップ）判断の前に、issue 自身のコメントと、関連するすべての PR（open / closed / merged）のコメント 3 種（ディスカッション `/issues/{n}/comments`、インライン `/pulls/{n}/comments`、レビュー `/pulls/{n}/reviews`）を必ず読むことを無条件で要求。「オープン PR がある」ことは、それ単独ではスキップ理由にならないと明記。
  2. 「振り返り（レトロスペクティブ）と自己改善ループ（必須）」節を新設。バッチ着手時に「なぜこれまで対応されずに残っていたのか」を自省して根本原因を特定し、プロセス改善を恒久ルール（本マニュアル / `docs/`）へ書き戻して独立した `chore:` 仕組み変更 PR として発行することを義務化。振り返りは本ログに日付付きで記録し、最終報告にも要約と仕組み変更 PR を含めることを必須化。
- **理由・期待効果**: コメントファーストの指針は既に「既存オープン PR の新規コメント対応」節に存在したが、埋もれていて参照されず遵守されなかった。その結果、オープン PR（PR #114 / issue #32、PR #113 / issue #109）に付いていたユーザーのエスカレーション済みコメントが未対応のまま放置された。前提条件を先頭へ移し、かつ自省→仕組み反映のループを制度化することで、同種の見落としを恒久的に防ぎ、改善が積み重なって加速する。
- **想定リスク**: 権限緩和・既存制約の削除は無し（既存の禁止事項はすべて維持し、制約の追加・明確化・再配置による強化のみ）。
- **状態**: 実装済み（本 PR）。
