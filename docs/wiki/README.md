# LLM Wiki（docs/wiki/）

- 最終更新日: 2026-09-03
- 対象範囲: LLM Wiki 全体の目的・置き場所・ページスキーマ・更新（最新化）ルール・過去ドキュメントとの整合性確保ルール・索引運用
- 出典/参照: issue #69 / `.kiro/agents/exam-content-maintainer.md`

## 目的

`exam-content-maintainer` エージェント（`.kiro/agents/exam-content-maintainer.md`）が作業を通じて獲得した知見を、**構造化して永続化**し、繰り返し利用・改善できるようにするための Wiki です。主に次の知見を蓄積します。

- より良い AWS 公式リソースを探すための**探索ノウハウ**。
- 全試験（`js/data/` 配下）のリソース**棚卸し状況**。
- 作業を振り返って得た**効率化・低コスト化（トークン削減）**の検討と、**自己拡張（プロンプト・skill の改善）**のログ。

この Wiki は、**最新化（棚卸しによる更新）と過去ドキュメントとの整合性確保が可能であること**を前提に採用しています。したがって本 README で定めるルールに従って運用しない Wiki ページは作らないでください。

## 置き場所

- すべての Wiki ページは **`docs/wiki/`** 配下に置きます。
- Wiki 以外の性質を持つドキュメントは Wiki に置かず、既存の置き場所（issue 解説は `docs/issues/`、要人間対応事項は `docs/action-required/`）を使います。
- ファイル名は内容が分かる英語スラッグ（例: `aws-resource-discovery.md`）にします。

## ページのスキーマ

各 Wiki ページは、**先頭にメタデータブロック**を、**末尾に更新履歴セクション**を必ず持ちます。

先頭メタデータブロック（箇条書き）:

- **最終更新日**: `YYYY-MM-DD` 形式。棚卸し・更新のたびに更新する。
- **対象範囲**: そのページが扱うテーマの範囲。
- **出典/参照**: 記述の根拠となる AWS 公式 URL や関連 issue / ファイル。

末尾の更新履歴セクション（`## 更新履歴`）:

- 各エントリは `- YYYY-MM-DD: 変更内容（理由・出典）` の形式。
- 情報を差し替え・削除した場合は、**何を・なぜ**変えたかを必ず残す。

推奨テンプレート:

```markdown
# <ページタイトル>

- 最終更新日: YYYY-MM-DD
- 対象範囲: ...
- 出典/参照: ...

## <本文の見出し>

...

## 更新履歴

- YYYY-MM-DD: 初版作成。
```

## 更新（最新化）ルール

- 棚卸し・追記のたびに、対象ページの**最終更新日を更新**する。
- 記述が古くなった場合は、**削除ではなく更新**を基本とし、変更した理由を**更新履歴に残す**。単純削除が妥当な場合も、削除した事実と理由を更新履歴に残す。
- 掲載する情報には、可能な限り**出典 URL（AWS 公式ドメイン等）**を付す。
- 定期的な棚卸しで、古い記述の更新・重複や矛盾の解消を行う。

## 過去ドキュメントとの整合性確保ルール

- ページ間・記述間で**矛盾を見つけたら、出典で最新・正確な側に寄せて統一**する。片方を残し、両者の関係（どちらへ寄せたか・理由）を**更新履歴に記録**する。
- **重複ページを作らない**。同じテーマは既存ページを更新して育てる。
- リンクは**相対パスで記述し、実在するファイル / 見出しを指すこと**（デッドリンク禁止）。
- 過去に書いた記述を上書きする場合も、**なぜ変えたか**が後から追えるよう更新履歴に残す。

## 索引運用

- Wiki ページを**新規作成・移動・削除**したら、索引 `docs/index.md` を**同じ変更（PR）で更新**する。
- **孤立ファイルを作らない**（`docs/index.md` から必ず参照される状態にする）。
- **デッドリンクを作らない**（索引・各ページの相対リンクが実在を指すこと）。
